# Code review: execution fidelity, stress testing, and translation trust

Date: 2026-07-19

## Scope

Reviewed the strategy schema/recap/compiler trust path, backtesting.py adapter, risk and scaled-exit behavior, data providers and caching, Monte Carlo/robustness analytics, translation ladder and eval harness, persistence/API boundaries, and the confirmation/dashboard frontend. The review preserved the two product invariants: the deterministic recap is still the confirmed executable contract, and engine metrics still pass through without downstream arithmetic.

## Correctness findings fixed

### P1 — Monte Carlo compounded the wrong quantity

The old bootstrap compounded each trade's `return_pct` as though every trade used the entire account. That is false for fractional sizing, pyramiding, scale-outs, and overlapping trades and could dramatically overstate both upside and drawdown.

`realized_pnl_bootstrap_v2` now samples engine-realized dollar P&L and accumulates each sample as a contribution to the run's original equity. This preserves the original trade sizing, commissions, slippage, and overlap effects without pretending to re-run the strategy. It requires at least 20 trades, rejects non-finite inputs, caps the in-memory workload, and explicitly discloses that sampled positions do not resize, serial correlation is removed, and drawdown is observed only at trade closes. Persisted legacy simulations are method-versioned out of the robustness score and must be rerun.

### P1 — scale-out tiers were not fractions of one logical position

backtesting.py interprets each fractional order against the buying power remaining when that order executes. Sending two `0.5` orders therefore produced roughly 50% then 25%, not two equal halves. Tier allocations are now converted into sequential engine fractions; a 50%/50% ladder produces equal-sized orders and remains one logical entry for pyramiding limits.

### P1 — batch runs silently ignored slippage

The setup form passed slippage to single runs but dropped it when extra symbols switched the flow to a batch run. Batch requests now carry both commission and slippage end-to-end, preventing systematically optimistic comparisons.

### P2 — repeated identical runs inflated robustness evidence

Running the same strategy on the same symbol, timeframe, date window, cash, and costs repeatedly increased the history score even though it added no independent evidence. History robustness now deduplicates exact test configurations while retaining the raw run count in its explanation. Thin Monte Carlo samples are also shrunk toward a neutral score until 100 realized trades support the distribution.

### P2 — requested data windows were not enforced consistently

The shared data boundary now rejects end-at-or-before-start ranges and clips cached and fresh provider frames to a UTC-normalized, start-inclusive/end-exclusive window. This prevents provider over-return or cache contents outside the requested range from leaking into a backtest.

### P2/P3 — supporting reliability issues

- API log/report limits now reject zero or negative values rather than passing SQLite's special negative-limit behavior.
- NumPy and Requests are declared direct backend dependencies because production modules import them directly.
- The Monte Carlo histogram no longer encodes negative/positive bins by red/green alone; it uses one distribution color with an explicit zero marker.
- Frontend linter warnings in chart tests and zero-byte workspace artifacts were removed.

## Requested product improvements

### Translation evaluation

The live corpus now has 55 cases and semantic category gates for nested boolean precedence, named sessions versus DST-aware local windows, exact OHLC/prior-bar relations, unsupported same-asset multi-timeframe requests, causal cross-asset context, invalid cross-source comparisons, and true pairs-trading clarifications. Cases include both paraphrases and adversarial wording. The extractor checks canonical boolean shape and exact operand relationships, not just whether an indicator name appeared. Overall accuracy must remain at least 90%; each category must remain at least 80%.

### Ranked vocabulary-gap report

`GET /api/translation-issues/report` builds a deterministic ranked phrase report from actual hard failures, escalation failures, and unresolved descriptions. Repeated rows count as occurrences but not independent descriptions, every displayed term is derived from the logged descriptions, and examples remain attached for human review. The operator dashboard now leads with this ranking and keeps the raw issue log available underneath.

### Confirmation execution policy

The recap page now always exposes the non-schema assumptions the user is also confirming: completed-bar signals, next-bar-open market fills, signal-close anchors for initial percent/ATR stops and targets, trailing-stop behavior, gap fills, OHLC-only intrabar resolution with pessimistic stop-first handling, and public-provider coverage/data limitations. It remains visible even while clarifications block acceptance.

## Remaining intentional limitations

- Monte Carlo is a trade-outcome bootstrap, not a market-regime generator or a substitute for walk-forward/out-of-sample testing.
- The engine has no tick path, bid/ask/order-book history, liquidity-aware fills, news, or fundamentals. Slippage is a configured per-side cost proxy.
- General same-instrument multi-timeframe rules and true two-leg pairs P&L remain unsupported; the translator now clarifies instead of misusing the one-instrument market-context filter.
- The clean-room engine remains a parity spike for a subset; the AGPL engine replacement is still required before paid hosting.
